# Scope after the demo

## Local data control
Add a clearly labeled **Delete all local Shakedown data** action so users can start again. Show exactly which app-owned data will be removed, offer a backup, and require explicit confirmation. Define how backups are handled; never delete STO combat logs or game files. Planned only; not implemented in 0.6.7.2.

## Current demo
Import real logs; inspect damage and survivability; record manual build versions; compare repeat runs. Include an accessible quick-start guide and standalone runtime in the portable Windows download.

## Equipment assistance, later
An observed-effects list could seed a user-confirmed equipment checklist. It must distinguish direct player weapons from pet weapons and named effects. Names seen under different firing modes should not automatically become separate equipped weapons. Effects can come from traits, consoles, other entities, or temporary powers.

Combat logs do not establish the complete loadout, equipped quantities, mark, rarity, modifiers, inactive gear, bank contents, or account-wide inventory. Any proposed mapping should retain evidence and ask the player to confirm it. Screenshots or manual entry can fill gaps.

Full account inventory deserves a separate model for characters, ships, items, quantities, locations, and ownership. It is outside today's demo. No automatic inventory completeness claim or deadline is implied.
